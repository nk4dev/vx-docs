# React components & hooks

`vx3` ships a ready-made `<Payment />` component plus hooks for payments and wallet connection. Import them from `vx3` or from the React-only entry `vx3/react`:

```tsx
import { Payment, useWallet } from 'vx3';
// or
import { Payment, useWallet } from 'vx3/react';
```

`react` and `react-dom` (18 or newer) are optional peer dependencies — install them in your app. The rest of the SDK loads without React; React is only required once one of these exports is used.

The demo apps generated by [`vx3 setup react`](/docs/commands/setup) and [`vx3 generate`](/docs/commands/generate) contain standalone copies of the same component and hooks, so you can edit them freely.

```tsx
import { Payment } from 'vx3';

<Payment
  to="0xRecipientAddress"
  amount="0.01"
  mode="wallet" // "wallet" uses window.ethereum, "api" posts to /api/pay
  onSuccess={(result) => console.log(result.txHash)}
  onError={(error) => console.error(error)}
/>;
```

## `<Payment />` props

| Prop | Type | Description |
| --- | --- | --- |
| `to` | `string` | Recipient address. |
| `amount` | `string` | Amount in ETH, as a decimal string (see Amounts below). |
| `mode` | `"api" \| "wallet"` | Payment path. |
| `currency` | `string` | Label sent to the API (default `ETH`). |
| `apiEndpoint` | `string` | Endpoint for `"api"` mode (default `/api/pay`). |
| `rpcUrl` | `string` | RPC URL forwarded to the API. |
| `onSuccess` | `(result: PaymentResult) => void` | Called with `{ txHash, receipt? }`. |
| `onError` | `(error: Error) => void` | Called on failure. |
| `className` | `string` | CSS class for the root container. |

## Payment modes

- **`wallet`** — requests accounts from the browser wallet (`window.ethereum`, e.g. MetaMask) and sends the transaction with `eth_sendTransaction`. The private key never leaves the wallet.
- **`api`** — POSTs `{ to, amountEth, rpcUrl, currency }` to `apiEndpoint`. [`vx3 api`](/docs/commands/api-server) serves `/api/pay`; it signs with the server's `PRIVATE_KEY` (or a dev account) and does not accept a private key in the request. Note that hooks default to `api` mode when `mode` is omitted.

`vx3 api` rejects browser requests from other origins. When your app runs on a dev server, start it with `--allow-origin <your app's origin>` — see "Using it from a frontend dev server" in [`vx3 api`](/docs/commands/api-server).

## Amounts

Amounts are converted from ETH to wei with exact string arithmetic, never floating point, so `"0.57"` is sent as exactly `570000000000000000` wei. An amount must be a plain non-negative decimal with at most 18 decimal places; anything else (`"abc"`, `"-1"`, `"1e18"`, 19+ decimals) fails with `Invalid amount: ...` before the wallet is asked to sign.

## Hooks

For custom UI, use the underlying hooks directly:

```tsx
import { usePayment, usePaymentStatus, usePaymentDialog } from 'vx3';

const { pay, state } = usePayment();
await pay({ to: '0xRecipientAddress', amount: '0.01', mode: 'wallet' });
```

| Hook | Returns |
| --- | --- |
| `usePayment()` | `{ pay(options), state }` — `pay` resolves with `{ txHash, receipt? }` and rejects with an `Error` on failure. |
| `usePaymentStatus()` | The current state (`status`: `idle \| pending \| success \| error`, plus `txHash` / `receipt` / `error`) with `setPending`, `setSuccess`, `setError` and `reset`. |
| `usePaymentDialog()` | `{ isOpen, open, close, toggle }` for wiring up a payment modal. |

## `useWallet`

Connects to a browser wallet through its EIP-1193 provider (`window.ethereum`) and keeps the account, chain and balance in sync.

```tsx
import { useWallet } from 'vx3';

function Wallet() {
  const wallet = useWallet();

  if (wallet.status === 'unavailable') return <p>No wallet detected.</p>;
  if (wallet.status !== 'connected') {
    return <button onClick={wallet.connect}>Connect wallet</button>;
  }
  return (
    <p>
      {wallet.address} on chain {wallet.chainId}
      <button onClick={wallet.disconnect}>Disconnect</button>
    </p>
  );
}
```

| Option | Default | Description |
| --- | --- | --- |
| `autoConnect` | `true` | Restore an already-authorized account on mount (no wallet prompt). |
| `provider` | `window.ethereum` | Use a specific EIP-1193 provider instead. |

| Returned | Type | Description |
| --- | --- | --- |
| `status` | `'unavailable' \| 'disconnected' \| 'connecting' \| 'connected'` | `unavailable` when no provider exists. |
| `address` | `string \| null` | Active account, lowercased. |
| `chainId` | `number \| null` | Chain ID as a decimal number. |
| `balanceWei` | `bigint \| null` | Balance of the active account in wei. |
| `error` | `Error \| null` | The last error (e.g. the user rejected the request). |
| `connect()` | `Promise<string \| null>` | Prompt the wallet; resolves with the address, or `null` on failure. |
| `disconnect()` | `Promise<void>` | Clear local state, revoking the permission where the wallet supports it. |
| `switchChain(chainId)` | `Promise<void>` | Ask the wallet to switch chains. Rethrows the wallet's error — code `4902` means the chain has not been added to the wallet yet. |
| `refreshBalance()` | `Promise<void>` | Re-read the balance. |

The hook follows `accountsChanged`, `chainChanged` and `disconnect` events from the wallet. The balance is re-read when the account or chain changes; call `refreshBalance()` after sending a transaction to pick up the new balance.
